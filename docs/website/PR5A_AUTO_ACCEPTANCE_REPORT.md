## 2. The four corrections

### D1. Statistics -> Browse membership drilldowns (P1 in PR-5, fixed)

**PR-5 defect, reproduced.** The status-chart link `#/browse?status=boundary_family&eng=1` carried no `group`.
Browse defaults to `group=member`, so the link opened **0** records while the bar said 509.

**Fix.** Every Statistics and Home link is generated by `web/src/lib/drilldown.ts` from the statistic's own
`denominator.id`:

| Denominator | Browse population | Size |
|---|---|---|
| `all_records` | `group=all&eng=1` | 5,466 |
| `counted_records` | `group=all` (engineered hidden; identical to `counts_eligible = 1`) | 5,460 |
| `members_candidates` | `group=member_candidate&eng=1` | 4,468 |

- Any other denominator gets no link: publications, PDB links, MRDB accessions, tree tips and watchlist are not
  Browse populations.
- A category filter that would leave the population also gets no link.
- Phylum/motif "Other" buckets and null categories get no link.
- Browse cannot express "Other" or "null", and these drilldown links promise exact equality with the bar.

**Evidence.**
- For all 453 drillable categories, `web_drilldown_golden_v160.json` stores n and the SHA-256 of the sorted source
  accessions. These come from hand-written SQL on the frozen DB (population predicate AND category predicate).
- `pr5a.test.ts` applies the website's real `applyFilters` to the query of each generated link and must reproduce
  every set exactly.
- `pr5a.spec.ts` clicks every rendered drilldown link on Statistics and Home in Chromium. It requires the Browse count
  to equal the bar's value; `boundary_family` now opens **509**.

### D2. Search -> Browse keeps structured semantics (P1 in PR-5, fixed)

**PR-5 defect, reproduced.**
- PR-5 offered "open all text matches in Browse" as `#/browse?q=MR_CLD3_017`.
- The Browse free-text filter searches fewer fields than Search, so it returned a different, smaller set.
- The link implied the two sets were equal.

**Fix.** `browseOptions()` builds structured Browse queries, all with `group=all&eng=1`:
- clade → `clade=`, then `clade=&tent=1`;
- subclade → `sub=`;
- PDB ID → `pdbid=`;
- exact helix-C motif → `motif=`;
- function class → `func=`;
- free text `q=` is always offered last.

Each option is evaluated with the real Browse filter against the complete set of text-search hits. The UI says
"the same records as this search" only when the **accession sets are equal**. Otherwise it says "not the same set as
this search" and gives the numbers. Options with 0 records are hidden. The old `q=` link was removed.

**MR_CLD3_017.** Checked independently against `v_master` in the frozen DB:

| Set | n | Same as search set? |
|---|---|---|
| Formal clade assignment, `clade=MR_CLD3_017` | **1,646** (0 engineered); set equals `v_master.clade_id = 'MR_CLD3_017'` | no (597 search hits not in Browse, 0 the other way) |
| Formal + tentative, `clade=MR_CLD3_017&tent=1` | 2,243 = 1,646 + 597 tentative | **yes** (identical sets) |
| Text-search hits | 2,243 | n/a |

The MR_CLD3_017 robustness caveat banner still appears on Browse whenever that clade is filtered.

**PDB 1C3W** maps to `pdbid=1C3W`. It gives 1 record, and that set equals `protein_pdb.pdb_id = '1C3W'`.

### D3. Keyed SQL reconciliation (P1 in PR-5 verification, fixed)

**PR-5 weakness.** PR-5 compared sorted value lists. That method cannot detect two categories whose counts are
swapped, a swapped crosstab cell, a dropped null category, or duplicate keys.

**Fix.** `web/scripts/summary_reconcile.py` (Python) and `reconcile()` in `web/src/lib/stats.ts` (browser recount
panel) compare complete keyed mappings:
- identical key sets, with null as a key of its own;
- identical value per key;
- duplicate keys rejected on either side;
- a key present on one side only rejected, even if its value is 0;
- total equal to the denominator.

**Result.** 58 items, all exact:

| Item type | Count | Method |
|---|---|---|
| Metrics | 34 | SQL replay |
| Distributions | 21 | SQL replay; `ncbi_phylum_counted` uses its stored SQL plus the stored derivation regex |
| Crosstabs | 2 | SQL replay |
| `tip_role` | 1 | No SQL exists; derived independently from `refpkg/MR_RT_003/tips.tsv` |
| **Total** | **58** | **57 SQL-replayed + 1 independently derived** |

The Python reconciliation tests now accept only that 57 + 1 split.

**Adversarial data mutations** (`tests/test_web_pr5a.py`). Every one must be rejected:
- swapped counts of two categories (evidence, membership group, phylum, `tip_role`);
- swapped crosstab cells;
- a dropped null category;
- a spurious null key;
- duplicate keys in exported items;
- duplicate keys in replayed SQL rows;
- a changed metric value.
